# 第17章｜时序逻辑中的 VHDL：从一次执行读懂一拍更新

## 本章要学什么

前面已经会从状态表设计时序电路，也会用VHDL写组合逻辑。现在要解决一个具体问题：同一段代码里明明先写第一条赋值、再写第二条赋值，为什么几个触发器仍然可以在同一时钟沿一起采样？如果把代码行的先后当成硬件动作的先后，移位寄存器、计数器和状态机都会读错。本章先把“语句何时执行”和“信号何时改变”拆开，再把它们接回真实电路。

阅读主线是：观察一个输入变化怎样唤醒进程，辨认条件选择的含义，读出寄存器在沿前和沿后的数值，最后组合出一个状态机。读完应能独立列出三位循环寄存器的逐拍表，解释组合过程为何需要完整赋值，从一段代码判断保存了什么、组合计算了什么，并用纸面事件表检查两进程模型。

正文依据《逻辑设计基础》第7版17.1—17.6节。例子标为“依教材某节自编”的，均为本笔记为解释语义设置的变式，不冒充教材原题。只在理解赋值时作必要的“信号与变量”辨析，不展开教材正文没有教授的变量式设计。代码沿用教材的显式敏感信号表、事件属性和数值包；纸面推导不代表已完成编译、仿真或器件验证。

## 一、进程、信号与更新：两种“先后”不能混在一起

### 本章路线
先从一根连线式的赋值回到输入变化，再引入可以容纳顺序语句的进程，最后给同一进程的一次执行列事件表。本章要解决的问题：“第二行是否一定读取第一行刚写的新值”。本章学完应会：能解释敏感信号表、信号赋值的预约含义和零物理时间内的更新轮次，并指出声明初始化与过程赋值的差别。

### 学习单元

#### 1.1 并发赋值描述持续存在的电路，进程描述被唤醒后的一段计算

信号表示电路中的连线值或寄存器输出；<=表示对信号安排新值，不是数学的“小于等于”。在第10章的结构体中，A <= B or C; 是并发信号赋值。这里的A、B、C都是信号，右端的or是逻辑或。它不是只执行一次的命令：B或C变化后，应重新算出A。因此可以把它理解成持续存在的或门，而不是处理器依次运行的一条指令。

**进程**是用process和end process包住的一段描述。进程本身与结构体内其他并发语句并列存在；进程内部的语句才按书写顺序执行。process(B,C)圆括号中的B、C称为**敏感信号表**，表示它们有变化事件时，进程需要恢复执行。事件指信号的值发生改变；重复赋相同值不一定产生事件。

~~~vhdl
process(B, C)
begin
  A <= B or C;
end process;
~~~

这个过程没有显式等待语句，执行到末尾后便等待敏感表中下一次事件。仿真开始时它还会先执行一次，以便建立初始组合结果。因此“只有输入第一次变化后才会执行”也不准确。begin标志进程正文开始，end process标志这段正文结束。进程被唤醒不等于A必然改变：若B从0变1而C原来已经是1，重新计算仍得到A=1。

硬件与代码的对应要分两层看。进程外有两个进程，不表示硬件先运行第一个再运行第二个；它们可以同时响应各自的输入。进程内有两条顺序语句，也不表示形成两级寄存器；是否需要保存，要看赋值条件和时钟，而不是看行数。

##### 小练习：哪些变化需要重新计算？

> 题源：依教材17.1、17.3节自编。

已知上述过程已经稳定在B=0、C=1、A=1。5 ns时B变为1，9 ns时C变为0，13 ns时B变为0。逐次写出进程是否执行，以及A稳定后的值。

解析：三次都发生敏感信号事件，进程均执行。5 ns时右端为1 or 1，A仍为1；9 ns时为1 or 0，仍为1；13 ns时为0 or 0，A更新为0。前两次“执行但无输出事件”正说明唤醒和输出变化不是同一件事。

#### 1.2 信号赋值先计算右端，再预约左端的新值

**信号**用于表达模块之间或进程之间可见的连线、寄存器输出。VHDL中的 <= 是信号赋值符号；此处并不是数学中的“小于等于”。执行 C <= A and B; 时，先读取当前A、B求出结果，再为C安排一次更新。没有after时也不应把它解释成下一行立刻看到C的新值。

**delta轮次**是仿真器在同一个物理时刻内部安排更新与重新计算的次序。教材用“△时间”表示不写显式延迟的信号也要经过一个更新步骤。它不等于一个实际时钟周期，也不是器件必有的某个皮秒数。我们用“t时刻第1轮更新”说明因果关系，比把它误写成“t+1 ns”准确。

考虑完整敏感表中的C是一个中间信号，初始A=B=C=E=0：

~~~vhdl
process(A, B, C)
begin
  C <= A and B;
  E <= C;
end process;
~~~

现在A、B在10 ns一起变成1。第一次执行中第一条语句为C预约1，第二条语句读到的C还是0，因此为E预约0。进程挂起后C更新为1；C在敏感表中，所以进程在同一物理时刻再次执行，第二次才为E预约1。经过后续更新，E变1。这不是“第二行等第一行算完再读新C”。

| 10 ns内的阶段 | 执行所读的C | 本阶段预约或可见的结果 |
| --- | --- | --- |
| A、B产生事件，第一次执行 | 0 | 预约C=1、E=0 |
| 第一次信号更新 | 更新后为1 | C产生事件，E仍0 |
| C事件使第二次执行发生 | 1 | 预约C=1、E=1 |
| 第二次信号更新 | 1 | E=1，过程稳定 |

同一进程、同一驱动、同一目标时刻的多次赋值，要看最后一条实际执行的预约。例如Q <= A; Q <= B; Q <= C; 中，若三条都执行且无不同延迟，Q最终采用C的值。不要把这条规则扩大成“不同进程给同一信号赋值时后写的进程获胜”；不同驱动并不是代码行优先级问题，本章电路让每个寄存器由一个更新进程负责。

##### 小练习：给中间信号补敏感表能改变什么？

> 题源：依教材17.3、17.6节自编。

把上例的敏感表改成process(A,B)，其余不变；仍从全0开始，让A、B在10 ns一起变1，以后不变。判断最终C和E，并说明能否靠交换两行解决。

解析：第一次执行后C变1、E仍0；因为C不在敏感表中，过程不会因C变化再次执行，E停在0。交换两行仍都读取旧C，不能修复。应使过程对所读的组合输入C敏感，或者直接写E <= A and B;，不再依赖内部信号更新。

#### 1.3 信号、变量和声明中的初始化各表达什么

读教材代码会看到 signal State : integer range 0 to 6 := 0;。signal表示信号，integer表示整数类型，range 0 to 6把允许取值限定为0到6。声明末尾的 := 0 是初始化，表示该模型开始时的取值，并非一个运行中的信号赋值。范围约束还让读者知道这里只需要表达七种状态。

**变量**是进程内可用于保存计算中间结果的另一类对象，变量赋值使用 :=，同一次执行中后面的语句可以立即读取赋给变量的新值。这正是它与信号预约更新的关键语义差别。但教材在20.5节明确说明正文没有展开变量式设计；本笔记只解释这个辨别规则，后面的可综合模型统一使用教材教授的信号，不另引入变量算法或相关库。

为了比较，不需要写一个教材外的变量设计。只要把两条规则说清：若对象是信号S，执行S <= 1;后下一条立即读取S，读到的仍是本轮可见旧值；若对象被明确声明为变量V，执行V := 1;后再读取V，得到1。把S <= 1错误改成S := 1不是“更快的写法”，而是对象种类不匹配。

初始化与复位也不同。初始化规定仿真模型起点；**复位**是实际控制输入触发的回到已知状态的动作。教材讨论的综合流程不能只凭声明的初值保证硬件上电状态，因此在要求可重复启动的电路里，应按设计给出复位或装载步骤。本章用“假定初值”做纸面计算时，会明确这是题目条件。

##### 小练习：同一个符号出现在两个位置

> 题源：依教材17.4—17.6节的信号声明和赋值规则自编；变量只作范围辨析。

给出signal Q : bit := '0';以及某上升沿分支中的Q <= D;。说明前一句何时起作用、后一句何时预约新值。若D=1而沿前Q=0，紧接着执行R <= Q;，R预约什么？

解析：:= '0'规定模型初始化值；Q <= D是在分支执行时预约Q=1。R <= Q读取本轮旧Q=0，因此预约R=0。R不会因为上一行“写了Q”就自动得到1。只有清楚对象、执行时刻和更新阶段，才能解释这种差别。

### 本章小结

进程是并发存在的描述块，块内语句顺序执行。敏感信号决定什么时候重新计算，信号赋值决定什么时候预约更新；两者都不能解释成处理器按行逐个改变硬件。delta轮次解决零物理时间内的因果排序。:=若出现在信号声明中是初始化；变量的立即赋值语义只在这里作辨别，后文继续使用信号模型。

### 本章练习与检验

> 题源：依教材17.6节自编。

假定A=0、B=1、C=0，在某次有效沿执行Q <= A; R <= Q; Q <= B;，沿前Q=0、R=1。分别写出Q、R的最终值和依赖的旧值，判断这是不是“Q先变0、再变1、R跟随两次”。

解析：Q的最后一次预约为1，R预约旧Q=0。更新后Q=1、R=0，不需要在外部显示一次中间的Q=0。R从1变0是因为读取了旧Q，不是读取最后一条语句预约的Q。检查时应在执行前先圈定旧值，再记录每个目标最后留下的预约。

## 二、条件和时钟：先知道什么时候执行，再决定执行哪条路

### 本章路线
先解释条件为真和分支优先级，再用时钟的变化事件区别边沿触发与电平透明，最后读出清零、置位和使能。本章要解决的问题：“时钟现在等于1是否足以说明采样”。本章学完应会：能从代码画出一个采样沿的动作，并在多个控制同时有效时给出唯一结果。

### 学习单元

#### 2.1 if、elsif和else把条件组织成有顺序的选择

if后面的条件是布尔表达式，即结果为真或假的判断。if A='1' then表示检查信号A是否等于逻辑1；比较中的等号并不改变A。then后是条件为真才执行的语句，else后是不满足前面所有条件时执行的语句，end if结束整个选择。

elsif是“否则再检查一个条件”，不是独立的第二个if。遇到第一个为真的条件后，其余elsif不再成为本次选择。以下给Clr清零、Ld装载、En使能计数建立优先级，Q是0到15的整数信号，D也是该范围内的数据，外层还要有时钟判断：

~~~vhdl
if Clr = '1' then
  Q <= 0;
elsif Ld = '1' then
  Q <= D;
elsif En = '1' then
  if Q = 15 then Q <= 0;
  else Q <= Q + 1;
  end if;
end if;
~~~

这里三个控制全为0就没有赋值。若它位于正确的边沿分支中，含义是这一拍保持原值。若它被直接用作无时钟的组合过程，缺少路径赋值就可能要求记忆；这个区别在第四节展开。不能看到“缺else”就跳过外层上下文宣布正确或错误。

若改成三个独立if，并让它们都给Q赋值，Clr、Ld、En同时为1时三段可能都执行，最后一段的赋值会覆盖前面预约。于是看似“清零写在最前面”，实际上它没有优先权。优先级来自条件链的互斥选择，而不是文字上先提到某个输入。

##### 小练习：清零、装载与计数冲突

> 题源：依教材17.1、17.2节自编。

Q沿前为9、D=6。连续三个有效沿的控制依次为(Clr,Ld,En)=(0,1,1)、(1,1,1)、(0,0,0)。使用上述条件链，列Q的沿后值；再说明把第三组En改为1会怎样。

解析：第一沿装载6，第二沿清零为0，第三沿保持0。若第三组En改为1，则从第二沿形成的旧值0计到1。判断每拍要承接上一拍结果；不能每行都从原始9开始，也不能在第一沿同时装载6再加1。

#### 2.2 上升沿是“刚变到1”，不是“现在是1”

时钟信号CLK的**上升沿**是逻辑0变为1的事件；下降沿是1变为0。教材用CLK'event检测CLK是否刚发生值变化，再用CLK='1'限制变化后的值。撇号后的event是事件属性，逻辑与and要求两个条件同时为真。对于本节使用的两值bit时钟，这就选中了0到1。

D是待采样的一位数据输入，Q是保存采样结果的一位输出；此例CLK按正常0、1两值变化。先固定这些角色，再读过程：

~~~vhdl
process(CLK)
begin
  if CLK'event and CLK = '1' then
    Q <= D;
  end if;
end process;
~~~

CLK的两个边沿都会唤醒进程，但下降沿时if条件不成立，因此Q不装载。D在两个沿之间变化也不唤醒这个进程；这是合理的，因为理想D触发器只在指定边沿采样D。相反，锁存器用process(G,D)，当使能G=1时执行Q <= D;，因此在整个高电平区间D都可能影响Q。

若只写if CLK='1'，同时敏感表又含D，CLK高时D每次变化都可更新Q，这与透明锁存行为一致，而不是边沿触发器。把D从敏感表删掉并不能把错误电平描述变成规范触发器模型；推断硬件要靠明确的边沿条件。

std_logic不仅有0和1，还包括前面讲过的未初始化等值。因此读这种事件判断时，本章时序例子都约定时钟正常在0、1之间切换，不把未知到1等异常变化纳入正常采样。教材采用event写法，本笔记也不突然改用未解释的其他边沿函数。

##### 小练习：画出一次采样，而不是一路跟随

> 题源：依教材17.1节自编。

初始CLK=0、D=0、Q=0。D在3 ns变1，CLK在5 ns变1，D在7 ns变0，CLK在10 ns变0，CLK在15 ns再变1。忽略显式器件延迟，给出各阶段Q。

解析：3 ns时Q不变；5 ns上升沿读取D=1，经过更新轮次Q变1；7 ns时Q保持1；10 ns下降沿仍保持1；15 ns上升沿读D=0，更新后Q变0。所谓“忽略器件延迟”并不是让同一执行中的读取改用新Q，delta更新原则仍在。

#### 2.3 异步复位、同步复位和使能必须分清所在层次

**异步清零**表示不用等待时钟边沿就可以令寄存器为0。低电平有效的ClrN在等于0时有效，名字末尾N只是提醒约定，真正行为由条件决定。它既要在敏感表中，又应先于时钟条件检查，否则无法表达独立于时钟的复位作用。下面CE是时钟使能，表示在有效沿才允许装载；D是输入，Q是一位保存输出。CE放在边沿条件内部，因此它独自变化不应立即改变Q。

~~~vhdl
process(CLK, ClrN)
begin
  if ClrN = '0' then
    Q <= '0';
  elsif CLK'event and CLK = '1' then
    if CE = '1' then Q <= D; end if;
  end if;
end process;
~~~

CE是时钟使能，含义为“在有效沿允许装载”。它放在边沿分支内部；CE独自变1不会立即改变Q，所以不必像异步清零那样放入触发器进程敏感表。ClrN从0回1只是释放复位，若没有同时发生合法边沿，Q继续保持0，直到以后允许采样。

**同步清零**则把Clr判断放在边沿条件内部。即使Clr在两个沿之间变1，也要等有效沿才能清零。教材74163计数器的清零就是这种行为。把清零从内层挪到外层会改变电路，不是排版差异。

若电路还有低有效异步置位SetN，可按“先清零、再置位、再边沿”写成if ClrN='0' ... elsif SetN='0' ... elsif 边沿 ...。当两者同时有效时，清零优先是这个模型明确规定的结果。它不能代替某个实物触发器数据手册对禁止输入组合的规定；描述模型与器件允许条件要分别检查。

##### 小练习：时钟没动，哪些输入仍能改变Q？

> 题源：依教材17.1、17.2节自编。

初始CLK=0、Q=1、ClrN=1、CE=0。2 ns时CE变1，3 ns时ClrN变0，4 ns时ClrN回1，5 ns时CLK变1且D=1。按上述异步模型求Q，再与同步清零模型比较。

解析：异步模型在2 ns不变，3 ns清零为0，4 ns继续0，5 ns采样D后变1。若同步模型的清零只在边沿内部且3—4 ns的短脉冲未跨越有效沿，则这次清零不会生效，Q保持1到5 ns，5 ns再装载1。两者最终相同不表示中间行为相同。

#### 2.4 JK触发器的内部信号把保存值与两个输出分开

教材17.1节还给下降沿JK触发器。J、K的特征规则已经学过：00保持、01清零、10置1、11翻转。用内部Qint保存状态，Q输出接Qint，反相输出QN接not Qint；这样过程里读取Qint，不必把输出端口当作内部可读寄存器。

异步低有效RN清零优先，SN置位其次，二者都无效才在下降沿求JK次态。下面after表示预约未来更新，8 ns用于复位/置位延迟，10 ns用于时钟沿后更新延迟；它不会暂停进程。次态式中Qint为旧值：

$$
Q_{\mathrm{int}}^+=J\overline{Q_{\mathrm{int}}}+\overline KQ_{\mathrm{int}}.
$$

~~~vhdl
Q <= Qint;
QN <= not Qint;
process(RN, SN, CLK)
begin
  if RN='0' then Qint<='0' after 8 ns;
  elsif SN='0' then Qint<='1' after 8 ns;
  elsif CLK'event and CLK='0' then
    Qint <= (J and not Qint) or (not K and Qint) after 10 ns;
  end if;
end process;
~~~

8 ns与10 ns分别是本教材模型给复位/置位与时钟更新设置的显式延迟。它们预约Qint在未来改变，不会让进程暂停8或10 ns；第六节再集中展开after与wait的差别。Qint改变后，两条并发输出赋值随之更新；把这两句搬到同一过程里若漏掉Qint的事件，就可能让Q、QN继续用旧状态。

##### 小练习：内部值变化后，输出怎样跟上？

> 题源：依教材17.1节JK模型自编。

初始Qint=0，RN=SN=1，J=K=1。20 ns下降沿之后假定没有其他事件，Qint应何时变为多少，Q与QN最终各为多少？为何不是下一行立即翻转？

解析：20 ns执行时用旧Qint=0算得1，预约30 ns更新Qint。30 ns状态变1后，并发输出关系使Q=1、QN=0。显式延迟控制更新目标时刻，后续输出在内部信号事件之后才重新计算，不是过程按行即时改值。

### 本章小结

if/elsif表达首先满足者优先，独立if表达分别检查；边沿判断表达一次采样，电平判断可能表达一段透明时间。复位在边沿外还是边沿内决定异步或同步，使能则只允许已有时钟沿执行装载。这些条件位置会直接改变硬件的保存与更新行为。

### 本章练习与检验

> 题源：依教材17.1、17.2节自编。

设计低有效异步清零、上升沿触发的T触发器。T=0保持，T=1翻转。给出过程，并从Q=0、ClrN=1开始，依次施加T=1的两个上升沿、T=0的一个上升沿以及无时钟时ClrN=0，求各次结果。

~~~vhdl
process(CLK, ClrN)
begin
  if ClrN = '0' then Q <= '0';
  elsif CLK'event and CLK = '1' then
    if T = '1' then Q <= not Q; end if;
  end if;
end process;
~~~

解析：Q依次为1、0、0、0。翻转式右端的not Q使用沿前旧值；第三沿不赋值表示保持；最后一次异步清零即使Q本来已经0也有效，只是不产生可见的新变化事件。

## 三、寄存器与计数器：一拍中的所有右端都读取沿前值

### 本章路线
先把一个触发器扩大成一组位，再用移位理解多目标同时更新，最后让控制决定保持、装载和计数。本章要解决的问题：“前一级已经写了新值，后一级会不会同一拍跟着跑过去”。本章学完应会：能标出每一位的旧值来源，并检查模数边界与控制优先级。

### 学习单元

#### 3.1 三位循环寄存器不是三条依次传递的新值

寄存器是一组共用更新条件的存储位。设Q1、Q2、Q3是三个位，它们在每个上升沿执行下面的过程。Q1接收旧Q3，Q2接收旧Q1，Q3接收旧Q2，连接成一个环。一个信号在过程里位于左端，只说明它得到新预约，不能立刻改写后面右端读到的旧值。

~~~vhdl
process(CLK)
begin
  if CLK'event and CLK = '1' then
    Q1 <= Q3;
    Q2 <= Q1;
    Q3 <= Q2;
  end if;
end process;
~~~

假定沿前Q1Q2Q3=100。先建立旧值栏，再一口气求三个右端：新Q1=0，新Q2=1，新Q3=0，所以沿后是010。第二拍再从010出发得001，第三拍回100。若算出000，说明把第一条对Q1的预约提前拿给第二条使用了。

| 有效沿次数 | 沿前Q1Q2Q3 | 本拍采样来源 | 沿后Q1Q2Q3 |
| --- | --- | --- | --- |
| 1 | 100 | Q3、Q1、Q2 | 010 |
| 2 | 010 | Q3、Q1、Q2 | 001 |
| 3 | 001 | Q3、Q1、Q2 | 100 |
| 4 | 100 | Q3、Q1、Q2 | 010 |

把三行代码交换顺序不会改变这个例子，因为它们分别给三个不同信号各赋一次值，且都读取旧值。但把三条信号赋值改成变量赋值会改变内部读取语义，因此不能借“代码压缩”无说明地更换对象。真实触发器也在同一沿采样各自D输入，并非一个Q变了之后才启动下一级采样。

##### 小练习：给环中放两个1

> 题源：依教材17.2节的三位移位例子自编。

将初值改为Q1Q2Q3=110，求前三拍并验证1的个数是否变化。如果第二行改成Q2 <= Q3;，同样求第一拍，解释为何不再是原来的循环。

解析：原模型110→011→101→110，每拍保留两个1。修改后第一拍新Q1=0、新Q2=0、新Q3=1，得到001；旧Q1没有被任何位接收，所以1的个数不再保持。验证连线时检查每一旧位是否恰好去一个新位置，比只背“循环移位”更可靠。

#### 3.2 向量切片和连接号决定每一位去哪里

声明Q : bit_vector(3 downto 0)表示四位向量，下标从3递减到0。Q(3)是这组约定中的最高位，Q(0)为最低位。Q(2 downto 0)是按2、1、0顺序取出的三位片段。连接符&把左右两段按书写顺序拼起来，不做加法，也不自动保留符号位。

左移一位的Q <= Q(2 downto 0) & Rin;表示旧Q2到新Q3、旧Q1到新Q2、旧Q0到新Q1，串行输入Rin到新Q0。右移一位则是Q <= Rin & Q(3 downto 1);。循环右移用旧最低位补到最高位，即Q <= Q(0) & Q(3 downto 1);。

对于旧Q=1101、Rin=0，左移得到1010，右移补0得到0110，循环右移得到1110。三个结果不同不是计算错误，而是最左或最右输入来源不同。算术右移若用于补码还要复制符号位，但本节教材寄存器模型先按明确连接关系读，不把所有“右移”都当除以2。

教材左移寄存器在时钟沿内部依次检查Clr、Ld、Ls。Clr=1清零，Clr=0且Ld=1装入并行输入D，否则Ls=1才移位。控制优先级决定装载和移位不能在同一拍依次发生。

~~~vhdl
if CLK'event and CLK = '1' then
  if Clr = '1' then Q <= "0000";
  elsif Ld = '1' then Q <= D;
  elsif Ls = '1' then Q <= Q(2 downto 0) & Rin;
  end if;
end if;
~~~

##### 小练习：先装载，再连续移位

> 题源：依教材17.2节自编。

旧Q=1101。第一沿Clr=0、Ld=1、Ls=1、D=0011；第二沿只有Ls=1且Rin=1；第三沿只有Ls=1且Rin=0；第四沿三个控制全1。列出每拍的位来源和结果。

解析：第一拍装载0011，Ls被优先级遮住；第二拍将011与1连接得0111；第三拍将111与0连接得1110；第四拍清零为0000。要解释“第二拍011来自哪里”，就回指第一拍形成的旧Q2Q1Q0，而不是继续引用最初1101。

#### 3.3 计数是受限范围内的寄存器更新，不是无限整数运算

计数器保存当前计数，再按条件预约下一计数。用整数范围0到15表达四位计数时，若Q=15还执行Q <= Q+1;，算术结果16超出声明范围；不能假设整数模型自动像四位导线一样丢弃进位。因此我们明确写满值回0。有限宽向量的截断和整数范围越界是两件事。

以三位模8计数器为例，Q允许0到7，En=1时在上升沿加1，7后回0。若有同步清零Clr与并行装载Ld，完整数据选择顺序可写成“清零→装载→计数→保持”，每一条边沿只选其中一条路。D的范围也应是0到7，否则装载本身就可能越界。

**终端计数输出**是表示“当前已经到末值且使能满足”的组合信号，不等于计数器已经完成下一次回绕。例如两级74163级联时，高位何时允许加1，要根据低位沿前的1111和使能条件确定。在同一个有效沿，高位加1、低位回0000；不是低位先回0后高位才寻找1111。

教材使用STD_LOGIC_UNSIGNED包为std_logic_vector提供无符号加法重载。若代码采用这个包，必须说明向量被当无符号数解释；不能只给std_logic_vector声明，就默认所有编译环境都知道“+”的数值含义。本章主要用显式整数范围讲清边界，第20章再按教材包统一写算术模型。

##### 小练习：两级计数器为什么能同沿进位？

> 题源：依教材17.2节级联计数思想自编。

两个四位计数器分别记高位H和低位L，都在上升沿更新。低位总使能，高位仅在旧L=15时使能；满值回0。初始H=2、L=14，求接下来三沿的(H,L)。

解析：(2,15)、(3,0)、(3,1)。第二沿的高位使能来自沿前L=15；尽管沿后L=0，高位仍已在该沿采样到有效使能。若把高位更新理解成“等L的新值出来再判断”，就会错过进位，正是旧值规则要防止的错误。

#### 3.4 74163把清零、装载与双使能写成一个同步选择

教材用74163说明控制端必须按真正规则读取。ClrN、LdN为低有效同步清零与装载输入；P、T是两个计数使能，只有两者都1才加1。Q为四位内部计数寄存器，D为四位并行输入，Qout持续反映Q，Cout为供级联使用的终端计数输出。

在每个上升沿，先检查ClrN=0就清零；否则LdN=0就装D；否则P=T=1才计数；其余保持。Cout=Q3 and Q2 and Q1 and Q0 and T，是组合输出，只看当前Q已到1111且T有效，不再额外乘P。高位计数器还需要自身P=1，所以“Cout可为1”与“高位本沿一定加1”仍不同。

若以教材的std_logic_vector四位Q配STD_LOGIC_UNSIGNED数值包，Q<=Q+1在结果位宽内回绕，1111后为0000；这是四位向量的数值解释。前面整数range模型必须显式写满值回0，两者不要混读。下表把一次同步优先选择固定下来，横线表示该输入在本行不影响结果：

| ClrN、LdN、P、T | 有效沿动作 | Cout如何决定 |
| --- | --- | --- |
| 0、-、-、- | Q清0000 | 仍由当前Q与T组合计算，沿后随Q更新 |
| 1、0、-、- | 装载D | 沿后由新Q重新计算 |
| 1、1、1、1 | Q加1 | 由沿前或沿后各自Q对应其时刻 |
| 1、1、其余使能组合 | 保持Q | 当前Q=1111且T=1时可为1 |

两个74163级联时，低位Cout接高位T，两个共用P与时钟。沿前低位1111、T=1、P=1，使高位在同一沿加1，低位回0000。内部字Qhigh与Qlow连接成八位后，教材用Conv_integer把这个向量换成整数供观察；转换函数只改变表示形式，不保存新计数，也不凭空添加一拍。

##### 小练习：终端输出为1却不计数

> 题源：依教材17.2节表17-1和级联模型自编。

旧Q=1111，ClrN=LdN=1，P=0、T=1，求沿前Cout与下一沿Q。随后保持P=0但令LdN=0、D=0110，再求下一沿结果。解释Cout不是独立启动命令。

解析：Cout=1，但P=0禁止计数，Q仍1111；装载有效后Q变0110，P不参与装载允许，沿后Cout变0。Cout只是级联的条件信息，高位是否动作仍要满足自身清零、装载和使能优先级。

### 本章小结

多位寄存器更新先列沿前值，再按每个目标的连接式求沿后值。切片和&决定位序，优先级决定本拍做哪一种动作，范围决定计数到哪里结束。只要这三层都明确，移位、装载和级联计数就不需要依赖模糊的“代码往下跑”。

### 本章练习与检验

> 题源：依教材17.2、17.5节自编。

四位寄存器带同步Clr、Ld、Ls，优先级同正文，初值1011。控制依次为装载D=1100、左移Rin=1、保持、左移Rin=0、清零。写沿后序列；再说明这个过程至少需要几位存储、左移输入需要怎样选择。

解析：1100→1001→1001→0010→0000。需要保存四位Q；每个D输入在清零0、装载数据、左邻位来源与保持之间选择。若器件有时钟使能，保持可以由使能关闭实现；因此不能凭代码行数直接宣称需要四个MUX或更多寄存器，实际映射还取决于目标器件。

## 四、组合进程：重新计算必须完整，不能靠记住上一次

### 本章路线
先说明组合电路不应依赖历史，再分别检查“什么时候重算”和“每条路径算出什么”，最后读懂case选择。本章要解决的问题：一个常见误会：为什么已经写成process，仍可能得到组合电路；为什么看似组合的代码又可能推断锁存器。本章学完应会：能从缺敏感项与缺赋值两种不同错误中找出根因。

### 学习单元

#### 4.1 组合完备包含输入响应与输出定义两个要求

**组合过程**表示当前输入确定后，输出就由当前输入唯一确定的逻辑，不应依赖上一次执行留下的值。为了正确表达这种关系，必须满足两个要求：所有会影响结果的被读信号变化时都要重新计算；对每一种允许输入组合，都要给每个输出一个确定值。前者是敏感表完整，后者是赋值路径完整。

例如过程希望实现Y=A and B，却只写process(A)。当B独自改变时，仿真过程可能不重新执行，Y留着旧结果。这不是电路本来需要保存历史，而是模型漏写了触发计算的输入。与此不同，process(A,B)里面若只在A=1时给Y赋B，A=0时不赋值，就明确要求Y保持旧值。

~~~vhdl
process(A, B)
begin
  if A = '1' then Y <= B;
  else Y <= '0';
  end if;
end process;
~~~

上例在A=0时固定输出0，所以是组合逻辑。删去else后，A=0时输出不更新，硬件为了保存旧Y可能需要锁存器。这种由条件不完整而产生保存功能的现象称为**锁存器推断**。它并不总是工具错误；工具只是照着描述实现了记忆，而设计者原本可能想要组合电路。

若本来就要透明锁存器，保留“门控打开时跟随、关闭时保持”的写法是合理的。问题在于设计意图与描述不一致。所以检查次态逻辑时不能机械补任意else，而要先写出每个输入条件对应的正确值。

##### 小练习：两段不完整各缺什么？

> 题源：依教材17.3、17.5节自编。

过程甲为process(A)中执行Y <= A and B;；过程乙为process(A,B)中执行if A='1' then Y<=B; end if;。从A=1、B=1、Y=1开始，先让B变0，再让A变0。分别解释甲、乙的行为和修正方向。

解析：甲在B变0时不执行，Y可能停1；A再变0时执行并算得0。应补B到敏感表。乙在B变0时执行，因A=1把Y更新0；A变0后无赋值，保持0。乙若要求组合与门，应在A=0时输出0；若要求锁存器，应承认这个保持就是设计功能。

#### 4.2 默认赋值先给完整背景，分支只改需要改变的部分

组合过程输出多时，可以在过程开头先给每个输出默认值，再由实际条件覆盖。默认值是本次执行的预约，并非“记住上一次”。例如一个选择器输出F，控制位Sel为0时选D0，为1时选D1：先F <= D0;，再if Sel='1' then F <= D1; end if;，每一条路径都对F有定义。

这与先前“同一驱动、同一目标时刻最后一次赋值优先”的规则吻合。Sel=1时第一句预约D0，后句改为预约D1，不要求外部先显示一次D0。Sel=0时保留的是本次已经给出的D0，不是F的旧值。

对状态机常见的默认Nextstate <= State;是“默认下一状态等于当前状态”的组合关系。State改变时仍会重算Nextstate。它不是无条件缺赋值，也不是把Nextstate自身回接。不要把Nextstate <= Nextstate;当作同等替代；后者需要读取并保留Nextstate的历史，已经改变依赖关系。

##### 小练习：默认值是否造成一次短促输出？

> 题源：依教材17.3、17.5节自编。

已知过程先写F <= D0;，再在Sel=1时F <= D1;。本次执行D0=0、D1=1、Sel=1，且无after。问F最终预约什么；能否单凭这两行推断“F必先掉到0再升到1”的真实毛刺？

解析：本次留下F=1的预约。不能从默认赋值的书写顺序推出真实毛刺，物理毛刺还取决于门级实现和延迟。这里证明的是行为描述的最终值，并非门级无冒险。前面已经学过的延迟与冒险需要在对应实现层次另行检查。

#### 4.3 case按表达式的取值选路，不是按条件优先抢占

case表达式is后面列when取值=>语句，含义为先求一个表达式，再选匹配的取值分支。例如Sel是两位bit_vector时，可能值恰为00、01、10、11，四选一MUX可以为每个值各列一条赋值。I0、I1、I2、I3是四个一位数据输入，F为一位输出，Sel为两位选择输入。=>是分支开始符号，不是信号赋值符号。

~~~vhdl
process(Sel, I0, I1, I2, I3)
begin
  case Sel is
    when "00" => F <= I0;
    when "01" => F <= I1;
    when "10" => F <= I2;
    when "11" => F <= I3;
  end case;
end process;
~~~

若Sel是std_logic_vector，除了四个二进制组合还可能含U、X等前面学过的逻辑值，必须考虑未逐项列出的取值。when others覆盖剩余选择；null表示这一分支不执行动作。对于希望完全组合的输出，others=>null可能留下旧值，不能因为“case覆盖所有取值”就认定“所有取值都给输出赋了值”。

if适合写具有先后优先级的条件，case适合按已确定对象的取值分组。教材还有when 1|3|5|7这样的组合选择，竖线表示列出的任一取值都进入同一段语句；它不是位运算。第20章会利用这一点合并多个行为相同的乘法状态。

##### 小练习：覆盖了分支，是否覆盖了输出？

> 题源：依教材17.3节自编。

Sel为std_logic_vector(1 downto 0)。四个正常分支给F赋值，others只写null。假定F先为1，之后Sel含X而进入others，问F会怎样；若要求遇到非正常选择时F固定0，如何改？

解析：null不安排新值，F会保持旧值1；这可能使组合描述携带不需要的存储含义。应让others分支明确F <= '0';，或在case前先给F默认0，others再null。非正常输入选择0是本例规定的处理策略，并非所有电路都必须采用该值。

### 本章小结

组合完整性要同时查敏感表与赋值路径。一个漏输入造成不及时重算，一个漏赋值可能造成保存历史，修复方法不同。默认赋值与case能把多路选择写清，但others存在不等于输出已确定，null也不等于自动输出0。

### 本章练习与检验

> 题源：依教材17.3、17.5节自编。

两位Sel选择I0、I1、I2，值11规定输出0。写一个组合过程，并用Sel从00变10、I2独自翻转、Sel变11的顺序检查。设I0=1、I1=0、初始I2=0。

解析：敏感表应含Sel、I0、I1、I2，四个case分支分别赋I0、I1、I2、0。初始F=1；Sel=10时F=0；I2变1时必须重新计算得F=1；Sel=11时F=0。若任一变化不能由代码给出这组结果，就回查敏感项和对应分支，而不是再加寄存器补救。

## 五、从状态表到两个进程：次态先计算，现态到沿才保存

### 本章路线
先用已学的现态、输入和输出读一张确定的状态表，再写组合过程和状态寄存器过程，最后比较门级与ROM实现。本章要解决的问题：“Nextstate算出来后为什么机器还没立刻进入那个状态”。本章学完应会：能追踪一次输入变化、一次有效沿以及由现态更新引起的再计算。

### 学习单元

#### 5.1 先读表里的对象，再写状态机代码

**State**表示当前保存在状态寄存器里的现态；**Nextstate**表示组合逻辑根据当前State与输入预先计算的次态。Nextstate不是第二组按拍保存的状态寄存器。对Mealy机，输出还依赖当前输入；对Moore机，输出只由当前状态决定。这些是前面状态表概念在代码中的名字。

教材表17-2给出一个BCD到余3码的串行转换器。BCD是把十进制0到9分别写成四位二进制，余3码是在该数值上加3再写四位。输入X与输出Z都按最低位先送；所以十进制5的BCD字0101实际输入顺序为1、0、1、0，其余3码1000应按0、0、0、1输出。

为避免靠图猜测，下面完整列出转换器的七个状态。每个单元的“下一状态/输出”都是当前状态和当前X确定的结果。S6的两个输入得到相同结果，并非让输出未定义。

| 当前状态 | X=0时的下一状态/输出Z | X=1时的下一状态/输出Z |
| --- | --- | --- |
| S0 | S1 / 1 | S2 / 0 |
| S1 | S3 / 1 | S4 / 0 |
| S2 | S4 / 0 | S4 / 1 |
| S3 | S5 / 0 | S5 / 1 |
| S4 | S5 / 1 | S6 / 0 |
| S5 | S0 / 0 | S0 / 1 |
| S6 | S0 / 1 | S0 / 1 |

S0是每个四位字开始前的状态。四个输入位应分别在四个有效沿前稳定，输出位也在对应沿前的组合稳定阶段读取。不能刚更新State就仍把Z当成本拍旧状态的输出；输入何时换位、输出在哪个阶段观察，必须随表一起约定。

##### 小练习：真正按最低位优先读一次表

> 题源：依教材17.4节表17-2自编输入验证。

初态S0，将十进制9的BCD四位按最低位优先输入。列出四次“现态、X、Z、次态”，再把输出还原成通常最高位写左边的四位字。

解析：9的BCD为1001，输入顺序1、0、0、1。四行依次为(S0,1,0,S2)、(S2,0,0,S4)、(S4,0,1,S5)、(S5,1,1,S0)。串行输出0、0、1、1，反向按通常位序写为1100，即12=9+3。输出回到四位字后才能做十进制比较。

#### 5.2 双进程模型把计算和保存明确分开

下面用整数0到6分别代表S0到S6，初始化0仅规定本例的纸面与仿真起点。X、CLK、Z均为bit。组合过程读取State、X，所以敏感表列这两个；寄存器过程只在CLK上升沿把旧Nextstate装入State。所有case分支都给Nextstate与Z赋值。

~~~vhdl
signal State, Nextstate : integer range 0 to 6 := 0;
-- 以下位于结构体begin之后
process(State, X)
begin
  case State is
    when 0 =>
      if X='0' then Z<='1'; Nextstate<=1;
      else Z<='0'; Nextstate<=2; end if;
    when 1 =>
      if X='0' then Z<='1'; Nextstate<=3;
      else Z<='0'; Nextstate<=4; end if;
    when 2 =>
      Nextstate<=4;
      if X='0' then Z<='0'; else Z<='1'; end if;
    when 3 =>
      Nextstate<=5;
      if X='0' then Z<='0'; else Z<='1'; end if;
    when 4 =>
      if X='0' then Z<='1'; Nextstate<=5;
      else Z<='0'; Nextstate<=6; end if;
    when 5 =>
      Nextstate<=0;
      if X='0' then Z<='0'; else Z<='1'; end if;
    when 6 => Z<='1'; Nextstate<=0;
  end case;
end process;
process(CLK)
begin
  if CLK'event and CLK='1' then
    State <= Nextstate;
  end if;
end process;
~~~

假定State=0、X原为0，组合稳定后Nextstate=1、Z=1。若10 ns时X变1，组合过程先算出Nextstate=2、Z=0，State仍是0。15 ns上升沿才使State采样沿前Nextstate=2。State更新后又唤醒组合过程；若X还为1，按照S2行得到Nextstate=4、Z=1。这样一个时刻附近可能有多轮计算，但状态寄存器只在一次有效沿采样一次。

这也解释为什么不应把两个进程想成“先永久跑完组合过程，再永久跑时钟过程”。组合电路始终存在；当状态、输入改变时重新稳定。时钟寄存器采样的是边沿前已经满足时序要求的组合结果。前章学过的建立和保持时间依然需要满足，行为级零延迟计算不替代这些物理约束。

##### 小练习：第二次计算有没有多走一拍？

> 题源：依教材17.4节自编。

沿前State=1、X=1，组合已稳定；该沿之后X暂不改变。列沿前Nextstate、Z，沿后State，以及因State事件再次计算出的Nextstate、Z。下一有效沿之前State会不会又变一次？

解析：沿前读S1得Nextstate=4、Z=0；该沿后State=4。随后组合过程按S4、X=1算得Nextstate=6、Z=0。下一沿前State仍保持4，不能因为Nextstate已为6就继续进入S6。组合次态变化不等于状态寄存器又受到一次时钟。

#### 5.3 同一状态机可以由逻辑方程、元件连接或ROM表达

行为模型直接写状态表，不指定每个门。结构模型实例化触发器、逻辑门等组件，再用内部信号连接。两种模型是否等价，要比较每个现态、每个输入的次态和输出，以及采样边沿；不能因为代码长度相近就认为电路相同。

教材17.4节还把状态与输入组合成ROM地址。ROM是只读存储器，此处保存的是固定的“给定现态和输入应得到什么”。若七个状态用三位编码，再加一位输入，地址共四位，对应16个地址；每个地址要输出三位次态和一位Z，共四位。三个D触发器保存当前状态，ROM输出的次态接它们的数据端。

例如地址由“现态三位、输入一位”按顺序组成。State=2的编码010，X=1时地址0101；表中下一状态4为100，Z=1，所以若约定数据字为“次态三位、Z一位”，该地址数据是1001。地址位序与数据字段若反过来，内容表也必须一起变，不能只改连接不改表。

未使用的状态编码111仍对应两个ROM地址。可以根据给定设计把它们写为回S0、输出0，也可以在教材允许的简化条件下作为无关项；两种选择的可恢复性保证不同。做确定的纸面验证时，本笔记采用明确输出和次态，不将无关项伪装成已证明安全的恢复行为。

##### 小练习：ROM的容量怎样随字段变化？

> 题源：依教材17.4节ROM状态机思想自编。

一个六状态Mealy机有两个二值输入、两个输出，现态用三位表示。若ROM地址按“现态、两个输入”组成，数据字按“三位次态、两个输出”组成，求地址数、字宽、存储位数和状态触发器数。

解析：地址5位，共32个；字宽5位，共160个存储位；状态仍需3个触发器。ROM有32行并不表示状态有32个，因为输入也占地址位。未使用状态编码对应的行仍需按设计处理，不能从容量计算直接推出其行为。

#### 5.4 状态方程模型仍然同时采样，结构模型只是把连线展开

状态表确定后，也可以按选定编码求出各状态位的次态方程，用一个时钟过程保存这些位。设Q1、Q2、Q3为三位编码，X为输入，某一教材编码下第一条次态关系为新Q1=not旧Q2、第二条为新Q2=旧Q1，第三条由Q1、Q2、Q3、X的逻辑式决定。三式都读取同一组沿前值，不因第一条先写而改变第二条输入。

如果每个赋值都写after 10 ns，三条预约都以同一个有效沿时刻为起点，在该沿后10 ns一起更新，而不是每条累加10 ns变成三级30 ns延迟。输出组合式若另写after 20 ns，它从自身右端输入事件发生时再预约更新；控制方程与输出方程的延迟起点要分别跟踪。

结构模型则把NAND门、反相器和D触发器实例逐个连接。port map中每个实际信号按组件声明的端口顺序接到输入或输出，实例标签只用于区分元件；不是按标签先后执行的函数调用。教材BITLIB包中已经声明了相关组件，所以源码可以直接实例化；若环境没有该教学库，必须提供相应元件模型，不能凭库名就宣称结构例子已编译。

ROM模型把固定真值表写成常量数组，数组下标是地址。向量地址要作为数组下标时，教材用Conv_integer转为整数；读出的字再拆为次态与输出。这个转换不改变逻辑编码本身，只把例如0101这组地址位解释为下标5。是否使用ROM、门或行为case，仍由相同状态转移关系检验。

##### 小练习：交换代码行能否改变状态编码？

> 题源：依教材17.4节方程与结构模型自编。

某沿前Q1=1、Q2=0、Q3=1，三条信号方程中前两条为Q1<=not Q2 after 10 ns;、Q2<=Q1 after 10 ns;。求两位在该沿后10 ns的结果。若交换这两行，或用两个同沿D触发器实例连接同一来源，会否改变结果？

解析：新Q1=1、新Q2=1，交换两行仍相同；两个触发器实例若分别接not Q2、Q1并共用边沿，亦采同样旧值。状态编码是给状态名称指定的二进制组合，不由源码行序决定。不同元件模型的显式延迟则要另核，不能只看连线就保证每个瞬间波形完全相同。

### 本章小结

双进程模型的主线是“组合过程先给候选次态和输出，寄存器到有效沿才接收次态”。State事件又会引起一轮组合计算，但不引起第二次寄存器采样。行为描述、门级连接和ROM内容可以表达同一状态表，等价性要逐行核对。

### 本章练习与检验

> 题源：依教材17.4节自编。

用完整表处理十进制5与十进制0两个连续BCD字，最低位先输入，初态S0。要求列两个字的状态路径、串行输出和还原后的四位余3码，说明两个字之间是否需要额外空拍。

解析：5的输入为1、0、1、0，路径S0→S2→S4→S6→S0，输出0、0、0、1，还原1000。0的输入为0、0、0、0，路径S0→S1→S3→S5→S0，输出1、1、0、0，还原0011。按四位字边界换入下一位即可，不需要额外空拍；条件是每位的输入稳定与输出采样时刻遵守前面的约定。

## 六、等待、延迟和综合：从说明中读出实际需要的电路

### 本章路线
先认识wait使进程停在哪一步，再用显式after比较执行顺序和更新时刻，最后把时钟、保持和组合计算对应到硬件。本章要解决的问题：“写了等5 ns，是否就得到一个精确5 ns的硬件”。本章学完应会：能分辨模型能表达的时间、综合可推断的结构和仍须另外验证的器件结果。

### 学习单元

#### 6.1 wait在当前位置挂起，三种形式等待三种条件

**wait语句**使不带敏感信号表的进程暂停。wait on A,B;等待A或B发生事件；wait for 5 ns;等待物理时间走过5 ns；wait until 条件;则在条件涉及的信号发生事件后重新检查，条件成立才继续。一个进程不能同时写显式敏感信号表和wait，这是教材采用的过程组织规则。

wait until A=B;并不是“执行到这里看见A=B就直接通过”的普通if。即使进入等待时A已经等于B，也应等待相关信号事件，再判断相等条件。wait until CLK'event and CLK='1';因此可以暂停到下一次上升沿。wait on对发生什么事件敏感，wait until还要求事件后的值满足条件。

教材说明，带敏感表的组合过程可以改写成“先执行正文，末尾wait on所读信号”。这两种写法都先执行一遍正文，再等待。若把wait放到开头，则第一次正文要等事件才发生，初始化行为也改变了。不能只根据“两个版本都有wait”就判定等价。

~~~vhdl
process
begin
  C <= A and B;
  E <= C or D;
  wait on A, B, C, D;
end process;
~~~

这个过程中C也在等待集合中，因为E读取C。进程末尾不是永久终止：被唤醒后从下一轮正文开始。写测试用激励时常在所有测试动作后放单独wait;，它没有继续条件，含义是让该激励进程停住；这属于测试描述，不能拿来代替硬件寄存器的使能。

##### 小练习：进入wait时条件已经为真

> 题源：依教材17.6节自编。

某进程在10 ns执行到wait until A=B;，此时A=B=0。12 ns时A变1，14 ns时B变1。问后续语句在哪一时刻恢复，若只写if A=B then能否表达同一等待？

解析：10 ns进入等待，不立即继续；12 ns事件后1不等于0，继续等；14 ns事件后A=B=1，恢复执行。if只在当前执行时选择是否执行分支，并不会把进程停到未来事件，因此不能替代这个等待。

#### 6.2 after预约未来更新，不让进程停在那里

信号赋值中的after时间表示这次赋值的目标更新时刻。执行A <= E after 10 ns;只是预约A的未来值，下一条语句仍在本次执行中立即计算；真正暂停进程的是wait，而不是after。若没有after，仍通过delta轮次更新。

假定20 ns上升沿恢复一个进程，它依次执行：A <= E after 10 ns;、B <= F after 5 ns;、C <= G;、D <= H after 5 ns;。其中E、F、G、H都在执行时读取，不是等到各自预约时刻才读取。于是C先在20 ns的更新轮次出现，B、D在25 ns更新，A在30 ns更新。

| 语句书写顺序 | 20 ns执行时读取的对象 | 预约更新时刻 |
| --- | --- | --- |
| A的赋值 | 当时E | 30 ns |
| B的赋值 | 当时F | 25 ns |
| C的赋值 | 当时G | 20 ns内后续delta轮次 |
| D的赋值 | 当时H | 25 ns |

若22 ns时E变化，但没有再次执行A的赋值，30 ns的A仍取20 ns读取到的E。这个例子固定一次执行且各目标不同，不涉及同一信号多次未来预约相互取代的更复杂波形规则；不要从它推导所有脉冲传播行为。

wait for 0 ns;只让出一个delta更新机会，不增加物理时间。它可用于理解仿真执行轮次，却不能证明等待后整个多级组合网络必已稳定；若依赖要经过多轮事件，一次等待只覆盖其中一轮。真正验证应明确需要观察的信号和稳定阶段。

##### 小练习：后写的一行能不能更早更新？

> 题源：依教材17.6节自编。

上例在20 ns执行时E=1、F=0、G=1、H=1。22 ns时E变0，其余不变，且没有新的时钟上升沿。给出C、B、D、A的更新时刻和写入值，并说明A为什么不读22 ns的新E。

解析：C在20 ns的delta更新为1；B在25 ns为0，D在25 ns为1；A在30 ns为1。A的右端早在20 ns执行赋值时计算了，after只改变左端更新的目标时刻，不推迟右端求值，也不暂停后续语句。

#### 6.3 综合检查的是保存和选择需求，不能把仿真语法当实物保证

**综合**是将VHDL描述转成逻辑元件与连接的过程。边沿分支中被赋值的位通常需要触发器；过程中的控制选择通常需要数据选择逻辑；纯组合计算不需要因为写在process里就增加寄存器。若赋值有意在某些时刻保持，工具会按描述推断存储或使能。

教材17.5节的累加器把四位A与B、进位输入相加，五位Addout保存四位和与最高进位。这里的**累加器**是既保存当前数又接收新和的寄存器，下一次相加继续使用上一次留下的A。Addout作为组合加法器输出，不是自动又增加一组五位寄存器。

控制Ld优先装载B，Ad其次把Addout低四位写回A，两者都无效则保持。即使组合加法器始终在算A+B，只有允许写回的有效沿才改变A。若把Addout的计算放到时钟过程里，再让A <= Addout;，A读到的是旧Addout，可能平白多出一级存储和一拍延迟。

after 5 ns用于行为仿真描述的延迟，教材指出综合工具通常忽略或要求删除这类延迟。wait for固定时间也用于仿真激励，不能因此得到一个可综合的精确时间等待器。实际速度要看综合、布局布线和时序分析结果，而不是看源码里写的ns数。

整数范围也要和预期状态数相符。0到7足够三位编码，0到6仍需三位；未限定范围的integer可能按较宽实现，教材以常见32位说明代价。本笔记不把这个历史工具示例当成所有工具、器件和版本的固定结论，而是要求综合报告核对实际位宽、寄存器与锁存器数量。

##### 小练习：额外一拍从哪里产生？

> 题源：依教材17.5节自编。

方案甲在进程外计算Addout=A+B，在时钟沿且Ad=1时A <= Addout;。方案乙在同一时钟分支先Addout <= A+B;，再A <= Addout;。给定沿前A=3、B=2、旧Addout=9，分别求这一拍A，判断两者为何不等价。

解析：甲沿前组合已稳定为5，所以写回5；乙第一条为Addout预约5，第二条仍读取旧9，A写回9。乙使Addout成为受边沿更新的存储对象，改变数据通路。只有明确要流水保存前次结果时才可能接受这种行为，本题要求的单拍累加不符合。

### 本章小结

wait决定进程在哪里暂停，after决定信号哪时更新；默认信号更新则靠delta安排因果。综合根据保存与选择需求推断电路，仿真中的时间标记不能直接制造精确硬件延迟。检查代码时，先问哪个对象必须保存、在哪个沿保存，再核对控制和组合输入。

### 本章练习与检验

> 题源：依教材17.3—17.6节综合自编。

一个模型要求上升沿装载四位D，否则保持Q，并用组合输出Z表示Q的最低位。请说明Q与Z分别放在哪里赋值；若Z也写在同一时钟分支，沿前Q=0010、D=0001时，本沿Z会是什么，为什么不符合“始终反映当前Q最低位”。

解析：Q在边沿过程内Q <= D;，Z在进程外Z <= Q(0);，或用对Q完整敏感的组合过程。正确模型更新Q后，Z在后续组合轮次反映1。若Z在时钟分支写Z <= Q(0);，它采样旧Q最低位0，因此滞后一拍并增加存储需求。改变赋值位置就是改变硬件层次。

## 九、自测参考答案

1. 两者交换，R=0、S=1。拆成两个同沿进程仍采样各自沿前值，结果不变；前提是没有引入额外驱动、延迟或不同边沿。不能把进程排列顺序当成跨进程的数据传递顺序。
2. 关闭时Q保持关门前的值，D变化不再传到Q，这是透明锁存器。若规定关闭时固定0，应补else Q<='0';，此时不再保存关门前的数据，而是一个组合选择关系。
3. 2的BCD是0010，输入顺序0、1、0、0。路径S0→S1→S4→S5→S0，输出1、0、1、0，还原0101，即2+3=5。每位Z取现态与该位输入的组合结果，不能在状态已跳到下一行后仍当成本位输出读取。
4. C在20 ns的delta更新，E在23 ns，A在28 ns。三条语句都在20 ns这次执行中完成预约，并未因after暂停；右端B、D、F也都在本次执行读取。后续值变化若未触发重新执行，不改变这次已经预约的数据。

## 十、复习公式卡

这里仅回收正文出现的关系。设Q为n位向量，Rin为一位串行输入，Q+表示有效沿之后的寄存器值，右端Q均为沿前旧值：

$$
Q^+_{\mathrm{left}}=(Q_{n-2},\ldots,Q_0,\mathrm{Rin}),\qquad
Q^+_{\mathrm{right}}=(\mathrm{Rin},Q_{n-1},\ldots,Q_1).
$$

状态机的组合关系与采样关系分别为：

$$
N=f(S,X),\qquad Z=g(S,X),\qquad S^+=N.
$$

其中S是现态、N是已算出的次态、X是当前输入、Z是Mealy输出；最后一式只在有效沿采样。Moore输出把第二式改为Z=g(S)。要表达m种状态至少需要满足下式的状态位数b；ROM地址若再含k个二值输入，字宽含b位次态与r位输出：

$$
2^b\ge m,\qquad N_{\mathrm{addr}}=2^{b+k},\qquad W_{\mathrm{word}}=b+r.
$$

公式卡不能替代过程的条件结构：异步复位、同步复位和使能是否有效，仍必须回到正文代码的所在层次判断。
