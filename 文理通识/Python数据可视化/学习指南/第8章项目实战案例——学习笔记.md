## 一、把业务问题变成可核对的数据口径（8.1—8.2）

### 本章路线

本章要解决的问题：先读什么、保留什么，才不会把行数当业务结论？本章学完应会：确定统计单位、清洗边界与时间分组，构造可复算的汇总。

### 学习单元

> 题源：依课程课件8.1—8.2及配套示例自编变式；本节小练习和检验同源，数据均为教学示例。

#### 先分清订单、订单明细、设备与用户

课件案例背景是广东8市、376台设备、2025年4—9月的交易与商品资料；这些是案例设定，不是本次重新统计结果。项目主线是原始资料→预处理→销售/库存/用户分析→报告。订单编号标识一笔订单，设备编号标识售货设备，用户标识可跨订单重复；一行若是订单明细，同一订单可能有多行。

因此订单数通常对订单编号去重计数，活跃设备数对设备编号去重，独立用户数对有效用户标识去重；销售额则先确认金额列是“该行商品金额”还是“整单金额”。若整单金额在每条明细重复，逐行求和会重复计入。先核对一行含义，再决定聚合。

下面用4笔独立订单示范；金额是每单金额，均为成功订单。此表以及后面所有计算是教学数据，不是课件案例的实际发现。

```python
import pandas as pd
orders = pd.DataFrame({
    "id": ["o1", "o2", "o3", "o4"],
    "user": ["u1", "u1", "u2", "u3"],
    "device": ["d1", "d1", "d2", "d3"],
    "city": ["A", "A", "A", "B"],
    "time": ["2025-04-01 04:59", "2025-04-01 05:00",
              "2025-04-02 12:00", "2025-05-01 20:00"],
    "amount": [10., 20., 30., 40.],
    "pay": ["WeChat", "WeChat", "Alipay", "WeChat"]
})
orders["time"] = pd.to_datetime(orders["time"], errors="coerce")
assert orders["time"].notna().all()
assert orders["id"].is_unique
orders["month"] = orders["time"].dt.to_period("M").astype(str)
monthly = orders.groupby("month").agg(
    sales=("amount", "sum"), order_count=("id", "nunique"),
    active_devices=("device", "nunique"))
```

四月应为销售60、订单3、活跃设备2；五月40、1、1。总额100、订单4、独立用户3。`assert` 检查已明确的前提，不是出现错误后自动丢弃不合格记录的清洗方法。

##### 小练习：一张订单展开为两行后怎样算

o1在两行明细均写整单金额10，o2一行金额20。逐行求和是多少？若目标是订单总额，应怎样恢复？

**答案：** 逐行相加为40，重复计入o1；确认同一订单金额一致后，按订单保留一条再合计为30。若金额实际是各商品明细金额，就不能套用此去重法。

#### 清洗与字段规约必须保留判据

按月读取文件后可 `pd.concat(parts, ignore_index=True)` 合并；合并前核对列名、编码与金额类型，合并后比较行数及重复订单。日期解析失败生成NaT（无有效时间），先统计并检查原值；金额用 `pd.to_numeric(...,errors="coerce")` 后也应检查失败记录。

课件删除少量缺失行并提取城市、统一商品名称，这是案例选择，不能推广为“任何缺失都整行删除”。只缺设备位置与缺金额对不同分析的影响不同。商品名称统一大小写、空白、末尾标点前，要确认这些差异并非真实规格区别。退款净额分析需保留退款字段；课件某任务删列不意味着所有问题都不需要该列。

字段规约是将较细信息转换成当前任务需要的形式。按课件时段边界，将小时分为凌晨[0,5)、早晨[5,8)、上午[8,11)、中午[11,13)、下午[13,16)、傍晚[16,19)、晚上[19,24)。左端包含、右端不包含，避免5点同时归两段。

```python
labels = ["Dawn", "Early", "Morning", "Noon", "Afternoon", "Dusk", "Night"]
orders["period"] = pd.cut(orders["time"].dt.hour,
    bins=[0,5,8,11,13,16,19,24], labels=labels, right=False)
```

样例04:59归凌晨，05:00归早晨，12:00归中午，20:00归晚上。月份用完整年月字符串，避免跨年时把两个四月混合。

##### 小练习：检查时间端点与缺失

11:00和13:00分别属于哪段？缺失时间能否填为凌晨0点以保证画图无空值？

**答案：** 11:00是中午，13:00是下午。不能随意填0点，会制造凌晨交易；应标未知并报告数量，或仅在时段分析排除且说明分母。

### 本章小结

原始一行的业务含义决定去重和求和方法，清洗与规约决定后面指标的可解释范围。保留原始数据与清洗计数，避免无依据覆盖。

### 本章练习与检验

原始100行，去除重复明细10行，另有5行缺城市但金额有效。城市分析与整体销售应怎样处理？

**答案：** 先确认10行确为重复再去重。整体销售可保留缺城市的有效交易；城市分析把5行标为未知或按明确规则排除，并报告金额覆盖范围，不能让两套总额悄悄不一致。

## 二、销售分析先拆规模与效率（8.3销售部分）

### 本章路线

本章要解决的问题：总销售高，是设备多、经营久，还是单机效率高？本章学完应会：计算订单、销售额、单机均值与排名份额，区分相关与因果。

### 学习单元

> 题源：依课程课件8.3销售分析及配套notebook 3.1—3.11及配套示例自编变式；本节小练习和检验同源，数据均为教学示例。

#### 总量、均值与有效分母

销售额是选定交易口径内金额之和；订单数是有效订单编号的去重数量；每单平均金额是销售额/订单数。单机平均销售总额是期间销售额/期间设备数，但设备数来自订单表时只能覆盖有交易设备，可能遗漏零销售设备。

在前节教学表中，A城销售60、订单3、有交易设备2，单机30；B城40、1、1，单机40。A总量更高，但按有交易设备平均时B更高。若A设备台账实际有3台（其中一台零销售），A全体设备平均应60/3=20，不能继续叫30为全体平均。

```python
city = orders.groupby("city").agg(
    sales=("amount", "sum"), n_orders=("id", "nunique"),
    active=("device", "nunique"))
city["sales_per_active_device"] = city["sales"] / city["active"]
city["sales_per_order"] = city["sales"] / city["n_orders"]
```

若设备上线天数不同，期间单机总额还受经营时长影响。要进一步比较日效率，需台账中的有效设备天数，不能只凭订单反推。画月份销售与设备数时，可用两个上下图共享月份；双轴必须分清元与台的单位，线条同升不证明“增加设备导致销售增长”。

##### 小练习：设备台账为何改变排名

A销售1000、有交易设备5、台账10；B销售800、有交易设备4、台账4。按两种口径均值各是多少？

**答案：** 有交易设备口径两城均200；全部设备口径A=100、B=200。台账缺失时只能准确称“有交易设备均值”，不能用它推断闲置设备比例。

#### TOP与BOTTOM先聚合，再排序

商品或设备排名要先按标识汇总，再排序，不能直接对原始订单取前10。相同商品名称不一定等于相同规格，优先使用明确商品标识；若商品信息只写在混合字符串中，应先解析，不能把整单金额无依据分摊给每个商品。

```python
device_sales = orders.groupby(["city", "device"])["amount"].sum()
top = device_sales.sort_values(ascending=False).head(10)
low_count = device_sales.lt(25).groupby(level="city").sum()
```

教学数据设备销售d1=30、d2=30、d3=40，阈值25下低销售设备为0。若未与完整台账合并，这个结果不包括“没有交易记录”的设备。求阈值设备数应先汇总期间销售再比较，不能把一次低金额订单当成一台低效设备。

假设城市总额1000，TOP2商品300、200，TOP2占全城50%；它们内部占比60%、40%。饼图仅放这两项时展示后者，想表达全城构成需加其他500。BOTTOM榜未出现完全无销售商品，也须与商品台账补齐才可讨论零销量。

##### 小练习：按订单筛低效设备错在哪

d1有10元和100元两单，d2只有20元一单。按期间销售额低于50定义低效，先筛订单金额低于50再数设备会错多少？

**答案：** 会数出d1、d2两台；正确是先汇总d1=110、d2=20，只有d2一台。筛选粒度错了，不是图形选择的问题。

### 本章小结

规模指标与平均效率回答不同问题，分母需覆盖真正讨论的设备。排名、阈值和份额都要建立在一致粒度的聚合结果上。

### 本章练习与检验

销售额从1000升至1200，设备数从10升至15，能否说单机效率提高？

**答案：** 同期同覆盖口径下，单机从100降至80；总量增加20%而设备增加50%。还应核对有效经营天数和设备范围，不能把总额增长直接写成效率提升。

## 三、库存与用户：先解释指标，再组织证据（8.3库存、用户部分）

### 本章路线

本章要解决的问题：卖得少、库存多和用户偏好分别需要什么分母？本章学完应会：按课件口径计算售罄与库存指标，区分订单份额和人数份额。

### 学习单元

> 题源：依课程课件8.3库存、用户分析及配套notebook 3.12—3.17及配套示例自编变式；本节小练习和检验同源，数据均为教学示例。

#### 售罄率与库存指标保留课程定义

课件以销售量/进货量定义售罄率，要求同商品、同单位、同期间，进货量非零。若当期还销售了期初库存，销售量可能大于当期进货，结果超过100%不一定是录入错，但提示当期进货不等于全部可售库存；不能直接截成100%。

例如A商品当月进货100件、销售40件，课件口径售罄率40%；B进货50、销售40为80%。合并售罄率是(40+40)/(100+50)约53.33%，不是两个比例的简单平均60%。原因是两商品分母不同，应按进货量加权。

课件“库存成本”使用销售单价×库存量。它可用于课程复现，但严格说更接近按售价估计的库存金额；真实采购成本应使用进价并遵守相应业务口径。本笔记把两者写清，避免将课程字段直接解读成真实利润或会计成本。

```python
stock = pd.DataFrame({"product":["A","B"], "incoming":[100,50],
    "sold":[40,40], "ending":[60,10], "sale_price":[5.,10.]})
stock["sell_through"] = stock["sold"] / stock["incoming"]
stock["inventory_at_sale_price"] = stock["ending"] * stock["sale_price"]
overall = stock["sold"].sum() / stock["incoming"].sum()
```

样例库存按售价估值为300和100，合计400。无退货、调拨、损耗且同期间时，期末库存=期初库存+进货−销售；用该平衡式审查数量。期末库存为时点数，通常不能把每月期末库存相加称作“期间累计库存”。

##### 小练习：超过100%先查什么

期初30、进货20、销售40、期末10。按课件售罄率是多少？是否违反库存平衡？

**答案：** 40/20=200%，但30+20−40=10，平衡成立。应说明口径受期初库存影响；若改为销售/全部可售50，则是80%，名称与定义必须一并交代。

#### 支付方式、城市与时段先确定统计单位

前节教学订单的微信3单、支付宝1单，因此微信订单份额75%。但微信独立用户是u1、u3共2人；支付宝独立用户u2共1人，样例对应2/3的用户份额。这两个比例不同，不能用 `value_counts` 的订单行数直接标“用户人数”。

```python
pay_orders = orders.groupby("pay")["id"].nunique()
pay_users = orders.groupby("pay")["user"].nunique()
period_orders = orders.groupby("period", observed=False)["id"].nunique()
```

若一人使用多种支付方式，各方式独立用户数可能重复，份额之和可能大于100%；要画互斥构成饼图，必须先定义“主支付方式”等一人一类规则，或直接画订单份额。城市也可能是设备所在城市，而非用户居住城市；同一用户可跨城消费，不能由交易地址推断其常住地。

时段长度不同，本案例凌晨5小时、早晨3小时、中午2小时等。原始订单数可以说明各时段交易规模，但若要比较每小时活跃强度，应再除以时段长度，并核对日期覆盖一致。分别报告“共多少单”与“平均每小时多少单”，避免将长时段天然较多的数量解释成更强偏好。

##### 小练习：同一用户跨方式时百分比为何超标

u1用微信和支付宝，u2只用微信，总用户2。微信、支付宝各有几人、占总用户多少？可以直接作为完整构成饼图吗？

**答案：** 微信2人占100%，支付宝1人占50%；重叠使合计150%，不能当互斥饼图。可画使用率条形并说明可多选，或改用订单口径。

### 本章小结

比例的关键是分母与集合是否重叠。库存有数量平衡与时点边界，用户分析有去重与归属边界；图标题应体现这些限制。

### 本章练习与检验

下午3小时共90单，晚上5小时共100单。哪个时段总量高、哪个每小时强度高？应怎样建议补货？

**答案：** 晚上总量100较高，下午30单/小时高于晚上20单/小时。结合商品结构、库存和具体峰值安排补货，不能只按总量认定晚上任何一小时都更忙。

## 四、把图变成可审查的报告结论（8.4）

### 本章路线

本章要解决的问题：怎样从现象走到建议，又不越过证据边界？本章学完应会：按背景、思路、结果、建议组织报告，将结论回接指标与限制。

### 学习单元

> 题源：依课程课件8.4及报告结构说明及配套示例自编变式；本节小练习和检验同源，数据均为教学示例。

#### 一条结论包含数值、比较口径与限制

课件报告结构是“背景与目的→分析思路→分析结果→总结与建议”。分析结果应先说图回答了什么，再给具体数值和比较口径；建议说明作用对象与核验办法，不能把图形走势直接写成已证实的原因。

完整示范：在相同观察期、设备台账覆盖一致的前提下，A城销售1000、10台，B城销售800、4台。A总额较高，但单机100低于B的200。可以建议排查A低销售设备的点位和在线状态；不能断言“A城市消费意愿低”，因为尚未控制经营天数、商品结构和缺货情况。

建议后的验证可比较排查前后同口径单机销售、缺货次数与有效营业天数，保留其他同时变化因素。这样“建议”有了可以检查的结果，而不是泛写“加强管理、提高效率”。

##### 小练习：改写超出证据的结论

“设备数与销售额同步增加，所以每增加一台设备必然增加同样金额。”现有证据只有6个月总量折线。应怎样改写？

**答案：** “六个月汇总中设备数与销售额呈同向变化；尚不能据此确定单台新增设备的因果收益。需补设备上线时间、同店同期表现与外部促销等资料。”这里区分观察关联与因果推断，不否认图中已看到的同步变化。

#### 总数勾稽与隐私检查是交付前的最后一道数据核验

总数勾稽指不同汇总层次应能对上同一总体：同口径各城销售相加应等于总额，月份合计也应等于总额；设备、用户的去重数不能随意跨组相加，因为同一对象可能跨月、跨城出现。前节示例各城金额60+40=100，月份60+40=100，两个维度都与订单总额一致。

```python
total = orders["amount"].sum()
assert abs(city["sales"].sum() - total) < 1e-8
assert abs(monthly["sales"].sum() - total) < 1e-8
```

金额浮点比较使用小容差；需要严格财务核对时应按统一的分或精确十进制处理。本课程报告至少保留数据来源、过滤规则、字段口径、图与解释。展示给公开读者时使用聚合结果，避免带出原始用户标识、订单编号和精确设备地址。

课堂项目的作业平台、截止时间和提交清单应以教师当次要求为准。本篇是课程原理学习文档，不填写报告模板、不补造未运行项目的发现，也不把notebook输出当作本次学习笔记的执行结果。

##### 小练习：人数为什么不能跨月相加

四月用户u1、u2，五月u2、u3，两个月用户数相加是多少，期间独立用户数又是多少？

**答案：** 月份计数相加2+2=4，期间独立用户数是3。u2跨月重复，不能把4写成期间用户规模；金额在不重复交易且口径相同时才通常可加。

## 本章综合习题测验

> 题源：依本章课件和前述教学内容自编综合题；全部数据为给定教学数据，非课程项目实测结果。先遮住解析独立作答。

### 第1题：查出重复金额

**题目：** 同一订单o1展开两行，每行都记整单金额30；o2一行20。表共3行、订单编号2个。应报多少订单、多少销售额？如无法确认金额列含义怎么办？

**解析与答案：** 订单2笔；确认是重复整单金额后销售50，不能逐行求和80。若字段实际为明细金额，逐行求和可能正确；字段含义未确定时先核对样本和字典，不能选择更好看的结果。

### 第2题：比较城市并补台账

**题目：** A总额1200、活跃设备6、台账设备12；B总额900、活跃3、台账3。计算两种单机均值，并说明“低于100设备数”为何不能只从订单表得出完整结果。

**解析与答案：** 活跃口径A=200、B=300；台账口径A=100、B=300。订单表未覆盖零交易设备；需以台账为底，按设备合并期间金额，对确认未发生交易者填0后筛选。还需核对上线天数，避免把未营业当作低效。

### 第3题：汇总售罄与库存

**题目：** 商品A进货100、销售40、期末60、售价5；B进货50、销售40、期末10、售价10，期初均0且无其他变动。给整体售罄、库存平衡和课件库存金额，并说明术语边界。

**解析与答案：** 整体80/150≈53.33%，不是(40%+80%)/2。A:0+100−40=60，B:0+50−40=10，平衡；按售价库存金额60×5+10×10=400。没有进价时不把它声称为真实采购成本或利润。

### 第4题：辨别支付与时段

**题目：** u1微信2单、支付宝1单，u2微信1单；下午3小时90单、晚上5小时100单。分别给微信订单份额、微信用户使用率及两时段小时强度，解释不能混画的比例。

**解析与答案：** 微信3/4=75%；微信用户2/2=100%，支付宝用户1/2=50%，用户集合有重叠，不是互斥构成。下午30单/小时、晚上20单/小时；晚上总量更高但每小时更低，不能把不同分母指标放入同一个构成饼图。

### 第5题：修正业务建议

**题目：** 报告写“五月销售由1000升至1200，设备由10增至15，所以设备效率提升，建议继续等比例扩张”；期间用户每月均100，便写两月用户200。修正这两点并列出补充依据。

**解析与答案：** 相同口径单机销售从100降到80，不能称效率提升；应核对设备天数、商品供给与点位后再评估扩张。两月用户可能重叠，须对用户标识在全期间去重，不能直接相加。建议同时报告总量、效率、覆盖期与用户去重结果，避免超出证据。

## 公式卡

- 每单平均金额=销售总额÷有效订单数；单机均值=同期间销售总额÷明确口径的设备数。
- 课件售罄率=销售量÷进货量（进货量大于0）；整体比例用总分子÷总分母。
- 无其他变动时：期末库存=期初库存+进货−销售。
- 课件库存金额=销售单价×库存量；采购成本估值需要进价。
- 互斥分类份额=本类数量÷同口径总数；重叠用户使用率不要求合计100%。
