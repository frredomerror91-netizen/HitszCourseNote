# 第二章｜数据的读取与处理

## 本章要学什么

本章贯穿的问题是：**如何把来源混杂、结构不明的原始文件，变成可以继续分析和绘图、并且能够被别人复核的数据表？**

学习顺序采用“读取 → 概览 → 类型统一 → 清洗 → 合并与重塑 → 导出验证”。先确认输入没有被错误读取，再处理数据质量，最后才进行聚合和输出；否则，后面的统计可能只是对错误数据的精确计算。

学完本章，你应能：

- 根据 CSV、Excel、数据库等来源选择读取函数和关键参数；
- 用 `shape`、`info()`、`head()`、缺失率和唯一键检查数据是否读对；
- 将日期、金额、分类和数值列统一为适合分析的类型；
- 根据缺失机制、重复记录和异常值的业务含义选择处理方法；
- 区分 `concat()`、`merge()`、`join()`、`combine_first()`、`groupby()` 和 `pivot_table()`；
- 输出清洗结果，并用行数、字段、关键指标和可复现代码完成结果核验。

> 阅读边界：本章聚焦 Pandas 数据读取与处理。具体可视化语法进入第四章；销售流水实验的提交规范以实验一指导书和 notebook 为准。

## 一、数据输入与可复核读取

### 本章路线

> 先识别文件和字段边界 → 再选择读取参数 → 再检查读取结果 → 最后测试写出后能否回读。 本节要解决的问题是：同一个文件即使能被 `pandas` 读入，也可能因为编码、分隔符、表头、工作表或索引处理错误而产生“看起来有数据、实际结构已错”的结果。本节建立读取阶段的最小证据链。 学完本节应会：选择 `read_csv()`、`read_excel()` 或 `read_sql()`；解释 `sep`、`encoding`、`usecols`、`dtype`、`nrows`、`chunksize` 和 `sheet_name` 的作用；读入后立即记录 `shape`、列名、前几行和类型；用 `index=False` 和 `encoding="utf-8-sig"` 导出适合继续使用的 CSV。

### 学习单元

#### 1. 把 DataFrame 当作数据接口

`DataFrame` 不只是一个二维容器，它还承载字段名、索引、类型和缺失值规则。读取阶段至少要回答四件事：文件路径是否正确、字段边界是否正确、表头是否正确、类型是否符合后续操作。

```python
import pandas as pd

sales = pd.read_csv(
    "实验一/实验一_销售流水_原始.csv",
    encoding="utf-8-sig",

print(sales.shape)
print(sales.columns.tolist())
print(sales.head())

```

CSV 读取时，中文文件常见的检查顺序是：分隔符 → 编码 → 引号与换行 → 表头/列名 → 选取列 → 类型。`nrows` 适合先试读，`chunksize` 适合大文件分块读取；不要在没有看过原始文件的情况下盲目指定 `dtype`。

## 二、概览与类型统一

### 本章路线

> 先看结构与分布 → 再识别字段语义 → 再统一日期、数值和分类类型 → 最后保存转换前后的对照。 本节要解决的问题是：统计函数不会替我们理解字段。字符串形式的金额不能可靠求和，未转换的日期不能稳定地按月统计，缺失的分类也不能在 `category` 类型上随意填入新标签。因此，本节把“看数据”和“改类型”连成一个可复核步骤。 学完本节应会：使用 `shape`、`head()`、`info()`、`describe()`、`value_counts()` 形成概览；判断一列应为日期、数值、分类还是文本；处理金额中的货币符号、单位和千分位；在类型转换失败时保留原值并定位异常记录。

### 学习单元

#### 1. 四步概览法

```python

print(sales.isna().mean().sort_values(ascending=False))
```

对分类列使用 `value_counts(dropna=False)`，对数值列使用 `describe()`。概览的目的不是抄输出，而是提出下一步可验证的问题：哪些列含缺失？键是否唯一？金额是否真的为数值？时间范围是否合理？

项目原始销售流水的字段为 `order_id`、`order_time`、`store`、`category`、`amount`、`quantity`。字段含义来自实验一资料，不应把清洗后的参考结果写成现场实测结论。

> 题源：`实验一/实验一：Python基础编程实践.pdf`“读取数据并使用 shape、info、head 等函数检查”；结合 `实验一_销售流水_原始.csv` 改写。

#### 2. 日期与金额的统一

```python
sales["order_time"] = pd.to_datetime(
    sales["order_time"], errors="coerce"
)

sales["amount_num"] = (
    sales["amount"].astype("string")
    .str.replace("¥", "", regex=False)
    .str.replace("￥", "", regex=False)
    .str.replace("元", "", regex=False)
    .str.replace(",", "", regex=False)
    .str.strip()
    .replace("", pd.NA)
    .pipe(pd.to_numeric, errors="coerce")
)
```

`errors="coerce"` 会把无法解析的值变成缺失，便于集中检查，但不能把转换失败静默当成正常值。应保留原列或记录失败行，确认失败原因后再决定修复、删除或标记。

#### 小练习：转换失败是否可以直接填 0

> 题源：项目原始销售流水与实验一指导书“日期、金额、分类、时间类型转换”任务；按原始情境整理。

对 `amount` 和 `order_time` 做转换后，分别统计转换失败数量。有人建议把所有失败金额填为 0，把所有失败时间删除。请审查这两个建议，并给出更稳妥的处理顺序。

**解析：** 先统计失败记录并查看原始值，再按语义处理。金额失败可能是货币符号、空字符串或非法文本，不能默认代表零；时间失败可能是格式变体或确实缺失，也不能未经检查直接删除。合理顺序是保留原值、记录失败掩码、尝试有依据的格式修复、按规则补值/剔除/标记，再比较处理前后行数与金额合计。

## 三、缺失、重复与异常值清洗

### 本章路线

> 先量化质量问题 → 再判断问题语义 → 决定修复、保留、标记或删除 → 用清洗前后对比证明没有误伤。 本节要解决的问题是：缺失值不一定是错误，重复行不一定都能删除，异常值也不一定是录入错误。清洗的核心不是“把特殊值变少”，而是让每条处理规则都有可解释的对象、条件和证据。 学完本节应会：用缺失率和业务语义选择删除、填充、插值或保留；用 `duplicated()` 判断重复范围，避免误删合法重复交易；用 IQR 等规则标记异常值，并区分“标记”与“删除”；比较清洗前后行数、缺失数、金额合计和关键分组结果。

### 学习单元

#### 1. 缺失值：先问“为什么缺失”

```python
missing_rate = sales.isna().mean().sort_values(ascending=False)
sales["store"] = sales["store"].fillna("未知门店")
sales_drop = sales.dropna(subset=["order_time", "amount_num"])
```

删除、常数填充、统计量填充和插值分别对应不同假设。时间序列插值要求顺序、时间间隔和变量含义合理；把“未参加考试”填成 0、把“未知门店”填成众数，都可能改变数据语义。

#### 小练习：按字段分别制定缺失策略

> 题源：`实验一/实验一：Python基础编程实践.pdf`“缺失值处理”任务；结合项目 CSV 改写。

对 `store`、`category`、`amount`、`quantity` 四列分别制定缺失处理规则，并说明什么情况下不能直接删除整行。

**解析：** 分类字段可以在业务允许时标记为“未知”；金额缺失通常不能直接用 0 代替，应核对原始记录或单独排除金额分析；数量缺失要确认是否代表未记录而不是零；订单时间或订单标识缺失时，记录可能无法定位，应优先回查原始数据。每条策略都要报告影响行数和指标变化。

#### 2. 重复值与异常值

```python
sales[sales.duplicated(keep=False)]
sales["order_id"].duplicated().sum()

q1 = sales["amount_num"].quantile(0.25)
q3 = sales["amount_num"].quantile(0.75)
iqr = q3 - q1
lower, upper = q1 - 1.5 * iqr, q3 + 1.5 * iqr
sales["amount_outlier"] = ~sales["amount_num"].between(lower, upper)
```

完全重复、订单号重复和金额极端值不是同一种问题。IQR 适合做异常标记，但“超出上下界”只说明它与总体分布不同，不能自动证明记录错误。保留 `amount_outlier` 通常比立即删除更利于审查。

#### 小练习：错误清洗方案审查

> 题源：项目实验一指导书“重复值、异常值处理”任务；按原任务改写。

某同学写了：

```python
sales = sales.drop_duplicates()
sales["amount_num"] = sales["amount_num"].fillna(0)
sales = sales[sales["amount_num"] < 1000]
```

指出至少三处风险，并给出改进方案。

**解析：** 未说明重复判定范围；金额缺失不一定是 0；固定阈值 `<1000` 没有业务依据，可能删除真实大额交易。改进方案是保留原始副本，先统计重复/缺失/异常数量，按业务键与字段语义分别处理，再比较清洗前后金额合计和分布。

### 本章小结

清洗规则必须能回答“处理了谁、为什么处理、处理后损失了什么信息”。下一节若要合并多表，应先保证主键、外键和缺失值状态可解释。

## 四、合并与重塑

### 本章路线

> 先识别表之间的关系 → 再确认连接键的唯一性 → 选择堆叠、关联或补齐方法 → 最后检查行数与未匹配记录。 本节要解决的问题是：`concat()` 按轴拼接，`merge()` 按键关联，`join()` 常围绕索引关联，`combine_first()` 用另一张表补齐缺失；它们都能得到一张表，但语义完全不同。统计前必须先说明关系，否则容易重复计数或静默丢行。 学完本节应会：根据数据关系选择 `concat`、`merge`、`join` 或 `combine_first`；用 `validate`、`indicator` 和连接前后的行数检查连接结果；用 `groupby()` 和 `pivot_table()` 完成分组统计与交叉汇总；解释长表、宽表和透视表之间的转换。

### 学习单元

#### 1. 四种连接语义

```python
all_sales = pd.concat([march, april], axis=0, ignore_index=True)

enriched = sales.merge(
    products,
    on="product_id",
    how="left",
    validate="many_to_one",
    indicator=True,
)
```

`validate="many_to_one"` 表示左表一个键可多行、右表每个键最多一行；它能尽早发现商品表键重复。`indicator=True` 会生成 `_merge`，便于统计未匹配记录。`inner` 会删除未匹配行，因此必须说明这种丢失是否允许。

#### 小练习：选择合并方法

> 题源：`课件/第一二次课/data/data` 中的 `订单商品明细.csv`、`商品信息表.csv`、`门店信息表.csv`，结合第二章课件“数据合并”部分整理。

判断以下任务应使用什么方法并说明理由：三个月表纵向追加；按 `product_id` 补充商品类别；用新表非空字段补齐旧表缺失值；生成“门店 × 商品类别”销售额交叉表。

**解析：** 依次是 `concat(axis=0)`、`merge()`、`combine_first()` 和 `pivot_table()`。第 4 项是改变汇总视角，不是按主键补充字段；误用 `merge()` 会得到明细连接而不是交叉汇总。

#### 2. 分组、聚合与透视

```python
by_store = (
    sales.groupby("store", dropna=False)
    .agg(order_count=("order_id", "nunique"),
         sales_amount=("amount_num", "sum"),
         quantity=("quantity_num", "sum"))
    .reset_index()
)

store_category = pd.pivot_table(
    sales, index="store", columns="category", values="amount_num",
    aggfunc="sum", fill_value=0, margins=True,
)
```

聚合前要确认统计对象：订单数通常用 `nunique`，销售额用 `sum`，客单价需要明确分子和分母。`fill_value=0` 代表该组合没有可汇总值，但若原始数据存在未知或缺失，不能简单把所有缺失都解释为零。

#### 小练习：连接后行数为什么变多

import pandas as pd

root = Path("实验一")
raw = pd.read_csv(root / "实验一_销售流水_原始.csv", encoding="utf-8-sig")
df = raw.copy()

before = {"rows": len(df), "columns": df.columns.tolist()}
df["order_time"] = pd.to_datetime(df["order_time"], errors="coerce")
df["amount_num"] = (
    df["amount"].astype("string")
    .str.replace("¥", "", regex=False).str.replace("￥", "", regex=False)
    .str.replace("元", "", regex=False).str.replace(",", "", regex=False)
    .str.strip().pipe(pd.to_numeric, errors="coerce")
)
df["quantity_num"] = pd.to_numeric(df["quantity"], errors="coerce")
df["store"] = df["store"].fillna("未知门店")
df["category"] = df["category"].fillna("未知类别")

q1, q3 = df["amount_num"].quantile([0.25, 0.75])
iqr = q3 - q1
df["amount_outlier"] = ~df["amount_num"].between(q1 - 1.5 * iqr, q3 + 1.5 * iqr)
df = df.drop_duplicates().reset_index(drop=True)
summary = df.groupby("store", dropna=False).agg(
    order_count=("order_id", "nunique"), sales_amount=("amount_num", "sum")
).reset_index()

df.to_csv(root / "实验一_销售流水_清洗_示例.csv", index=False, encoding="utf-8-sig")
summary.to_csv(root / "实验一_销售流水_门店汇总_示例.csv", index=False, encoding="utf-8-sig")

## 六、练习提示与常见问题

- 先写对象、字段语义、已知条件和求解目标，再选择函数。

## 九、自测参考答案

### 1. 为什么读取成功不等于数据正确？

文件可能被错误分列、误读编码、把表头当数据，或把金额、日期读成字符串。至少要检查列名、行列数、前几行、类型、缺失率和关键字段格式。

### 2. 三个函数的关系是什么？

`concat` 按轴堆叠已有表；`merge` 按键建立表间关系；`pivot_table` 按索引、列和值重新组织汇总。它们解决的不是同一层问题。

### 3. 金额转换失败能否填 0？

不能默认填 0。先保留原值、统计失败记录并判断是空值、货币符号、格式错误还是业务缺失；只有题源或业务规则明确缺失等于零时才可这样做。

### 4. 合并后行数变多如何排查？

检查右表连接键是否重复、关系是否与预期一致、是否发生一对多或多对多展开；使用 `validate`、`indicator`、连接前后主键数量和金额复算定位原因。
